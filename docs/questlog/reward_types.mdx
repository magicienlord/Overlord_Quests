title: Reward Types

---

Quest rewards are defined in the `rewards` property of a quest. They are a list of reward objects, each of which can be one of the following types:

### `questlog:item`
Gives the player an item.

#### Properties
- `item`: The item to give the player.
- `count` (optional, default: 1): The amount of the item to give the player.

### `questlog:command`
Runs a command as the player, at the player's position. If `permission_level` is specified, the command is run with that permission level.

#### Properties
- `command`: The command to run.
- `permission_level` (optional, default: 2): The command's permission level when run as the player. The player does not need to possess this permission level themselves. See: [Java Edition Commands - minecraft.wiki](https://minecraft.wiki/w/Commands#Available_in_Java_Edition)

Command rewards are privileged server-side actions. Treat their definition data accordingly.

### `questlog:experience`
Gives the player experience.

#### Properties
- `experience`: The amount of experience to give the player.
- `levels` (optional, default: false): Whether to give the player levels instead of experience points.

The property is `levels`, plural. Older documentation incorrectly called this field `level`.

### `questlog:loot_table`
Gives the player loot from a loot table. The loot context is set as follows:
- This entity: player
- Origin: player's position
- Killer entity: player
- Level: the world the player is in

#### Properties
- `loot_table`: The loot table to give the player. If the table does not exist, Questlog logs an error.

### `questlog:choice`
Lets the player choose a fixed number of rewards from a list.

#### Properties
- `choices`: A list of non-choice reward objects available for selection.
- `pick_count` (optional, default: 1): The exact number of unique choices the player must select. It must be at least 1 and cannot exceed the number of entries in `choices`.

#### Current protocol restrictions
- A `questlog:choice` reward cannot use `auto_claim`, because a valid player selection is required before it can be claimed.
- Nested `questlog:choice` rewards are not supported. The current client-to-server claim packet carries the selected indices for one top-level choice reward only and cannot represent a second nested selection state.
- The server validates the exact selection set before applying any reward.

Example:

```json
{
  "type": "questlog:choice",
  "pick_count": 1,
  "choices": [
    {
      "type": "questlog:item",
      "item": "minecraft:iron_ingot",
      "count": 4
    },
    {
      "type": "questlog:experience",
      "experience": 50
    }
  ]
}
```

### Base Reward Properties
All non-choice reward types support the following optional properties:

- `auto_claim` (optional, default: false): If set to `true`, the reward is given automatically once the quest is completed, without requiring manual collection.
- `claim_sound` (optional): The sound to play when the reward is claimed.
- `name` (optional): The name of the reward. If omitted, a name is generated from the reward type.
- `icon` (optional): The icon to display for the reward.
- `translatable` (optional, default: false): Whether the name is a translation key.

`questlog:choice` supports the display properties above but deliberately does not permit `auto_claim=true` in OVERLORD QUESTS.
